# Setup, deployment and showcase guide

This takes you from the bundle file to a public, working demo link. All commands are for
**Windows PowerShell** on your personal laptop.

---

## Part 1: Update your personal laptop copy (5 min)

You already have `switch\authorityguard` from Weeks 0–1. Copy **`authorityguard-full.bundle`**
into the `switch` folder (next to `authorityguard`, not inside it), then:

```powershell
cd switch\authorityguard
git pull ..\authorityguard-full.bundle main
git log --oneline -3
```

**What happens:** Git adds every new commit (Week 2 → v1.0.0) to your copy. `git log` should show
`v1.0.0` at the top.

## Part 2: Run it locally (10 min)

```powershell
Remove-Item -Recurse -Force .venv            # old environment (office-laptop paths)
python -m venv .venv
.venv\Scripts\Activate.ps1                   # if blocked: Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
pip install -e ".[dev]"
pytest                                        # expect: 166 passed
alembic upgrade head
uvicorn apps.api.main:app --reload
```

Open **http://127.0.0.1:8000/dashboard** and click **▶ Run demo (auto-approve)**.

| Command | Why |
|---------|-----|
| `pip install -e ".[dev]"` | Installs FastAPI, LangGraph, PyJWT and the other packages from `pyproject.toml` |
| `pytest` | Proves your laptop reproduces the results (unit, integration, adversarial, benchmark) |
| `alembic upgrade head` | Creates the 8 database tables in `authorityguard.db` |
| `uvicorn …` | Starts the web server. `--reload` restarts it when code changes |

Stop the server with **Ctrl+C**.

## Part 3: Push to GitHub (2 min)

```powershell
git push
```

Then open **https://github.com/Vaishnavit08/authorityguard/actions**. The **CI** run has 5 jobs:

| Job | What it proves |
|-----|----------------|
| Tests (SQLite, Python 3.12 / 3.13) | All 166 tests and lint pass |
| Tests (PostgreSQL 16) | Works on a real production database, migrations up and down |
| Security benchmark | 139 scenarios, fails if any attack succeeds. Report is in the run summary |
| Docker image smoke test | The container builds, starts, protects admin endpoints and runs the demo |

All green means the project is verified end to end, including Docker, which neither laptop has.

## Part 4: Deploy publicly on Render (10 min, free)

Render builds the `Dockerfile` straight from GitHub and gives you an `https://…onrender.com` link.

1. Go to **https://render.com** and sign up with **GitHub** (your Vaishnavit08 account).
2. Click **New +** → **Blueprint**.
3. Connect the **authorityguard** repository. Render reads [`render.yaml`](../render.yaml) and shows
   one web service called `authorityguard` on the **Free** plan.
4. Click **Apply**. The first build takes about 5 minutes. Watch the logs until you see
   `Uvicorn running on http://0.0.0.0:…`.
5. Open `https://authorityguard-XXXX.onrender.com/dashboard` (Render shows the exact URL) and run the demo.

What `render.yaml` sets up for you:

| Setting | Value | Why |
|---------|-------|-----|
| `AG_ENV` | `demo` | Allows an automatically generated signing key |
| `AG_ADMIN_API_KEY` | random (generated by Render) | Visitors can't create users or issue capabilities directly. The demo button uses the key internally |
| `AG_DATABASE_URL` | SQLite inside the container | No database to provision |
| `healthCheckPath` | `/health` | Render restarts the service if it stops answering |
| `autoDeploy` | true | Every `git push` redeploys automatically |

**Free-plan behaviour:** the service sleeps after about 15 minutes idle, and the first visit then takes
30–60 seconds to wake up. Data and the signing key reset on restart, which is fine because everything
is synthetic. **Open the link a minute before a demo or interview.**

Finally, put your live URL into the README (`> **Live demo:** …` line) and push again.

## Part 5: Showcase it

**On GitHub**
* Repo → ⚙️ next to *About* → Website: your Render URL. Topics: `ai-security`, `agentic-ai`,
  `authorization`, `langgraph`, `fastapi`, `llm-security`, `zero-trust`.
* Profile → *Customize your pins* → pin `authorityguard`.

**3–5 minute demo video** (record your screen with the Xbox Game Bar: Win + G, or OBS)

| Time | Show |
|------|------|
| 0:00 | The problem: a sub-agent can do more than the human intended. One sentence on confused deputy and prompt injection |
| 0:30 | Dashboard → **Run demo — I'll approve**. Walk through the steps table: injected email **denied**, stolen token **denied**, HR file **denied** |
| 1:45 | The pause: click **Approve**, the email is sent once. Replay and swapped body are **denied** |
| 2:30 | Delegation chain panel: alice → research-agent → extract-agent with narrower scopes. Audit trail: no tokens, no document text |
| 3:15 | `docs/benchmark-report.md`: 139 scenarios, 100% → 0% attack success, 0% false blocks, ~5 ms decisions |
| 4:00 | Limitations (from the README) and what you'd build next |

**Two-line pitch for your CV or LinkedIn**
> Built AuthorityGuard, a delegated-authorization gateway for multi-agent AI. Signed Ed25519 capability
> tokens are attenuated across agent delegation, a deterministic policy engine decides every call,
> and human approvals are hash-bound and single-use. Attack success went from 100% to 0% across 139
> adversarial scenarios at ~5 ms per decision (FastAPI, LangGraph, PostgreSQL, Docker, CI).

**Interview talking points**
* Why the LLM is never the authority, and where the trust boundaries are (see the threat model).
* Attenuation: why a child scope must be a subset of the parent's, and how `pattern_within` proves it.
* Why approvals are bound to a hash of the exact action (approval swap) and single-use (replay).
* A real bug the tests caught: approval previews leaked document text into the audit log. That's
  why redaction has its own tests.
* What it does **not** solve: misuse *within* a granted scope, and tools that bypass the gateway.

## Optional: run with Docker locally

If you install Docker Desktop later:

```powershell
docker compose up --build
```

This runs the API with PostgreSQL at http://127.0.0.1:8000/dashboard. The admin key defaults to
`change-me-local-only`. Override it with `$env:AG_ADMIN_API_KEY = "…"` before running.

## Troubleshooting

| Problem | Fix |
|---------|-----|
| `Activate.ps1 cannot be loaded` | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass`, then activate again |
| `ModuleNotFoundError: apps` | Run commands from inside the `authorityguard` folder |
| `no such table` | Run `alembic upgrade head` |
| Render build fails | Open the deploy logs. The same Dockerfile is tested by the CI *Docker* job, so compare with it |
| Render URL very slow at first | Free plan waking up. Wait about 60 s |
| Demo says `rate_limited` | More than 20 runs in a minute. Wait a minute |
